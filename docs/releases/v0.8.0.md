# Homelab Atlas v0.8.0

> **Archive:** this page describes an earlier upstream release. Discovery features mentioned here are not part of the current build. See the [current release notes](/releases/v0.12.1).

Released October 28, 2026.

## Nmap XML import

**Discover devices** now accepts a user-supplied Nmap XML file. Atlas does not run Nmap or probe a network. It normalizes explicitly up hosts and open TCP/UDP endpoints into the existing unchecked review, including ping-only hosts, IPv6, hostnames, vendor text, and canonical MAC addresses.

A network name namespaces stable identities. Reuse it for later scans. MAC identity survives an IP change; without a MAC, an IP change creates a new identity, and changing between MAC-present and MAC-absent can also appear new. Files, scan times, product versions, and XML ordering do not define identity. Multi-host files stay open so each host can be reviewed and applied separately.

## Safe merging

Host rows can add an empty **Network host** card or link to an existing card. Endpoint rows add or link services. Existing device metadata, services, connections, positions, and widths are not rewritten. New cards go below existing cards; growth that would overlap another card is blocked. Each Apply is one undo step.

Schema version 6 adds device-level host bindings. Valid schema versions 1 through 5 migrate while preserving existing data and manual layout.

## Privacy and limits

The selected XML reaches only the user's Atlas backend transiently. NSE/script output, command arguments, traces, service fingerprints, and unknown fields are discarded from normalized review. Retained hostname, vendor, service, product, and version text can still be private or credential-like. Imports are limited to 2 MB, 256 host records, 1,000 findings, and 64 nesting levels. Applied IP facts remain in JSON but can be hidden in SVG/PNG with the existing privacy filter.
